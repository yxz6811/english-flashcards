# Research: 期末英语闪卡复习 Web 应用

## 决策 1：前端框架与渲染模式

- **Decision**: 采用 Next.js App Router 作为主框架，使用客户端交互为主、服务端路由辅助的模式。
- **Rationale**: 兼顾高交互学习体验与 BFF 能力，可统一处理页面与 API 代理，降低项目拆分成本。
- **Alternatives considered**:
  - 纯 React + 独立后端：灵活但工程拆分成本更高。
  - 仅前端静态站点：难以安全管理 OCR/AI 服务密钥。

## 决策 2：状态管理与学习规则承载

- **Decision**: 使用轻量全局状态管理承载“当前学习队列、生词本、正确连击、撤销栈”。
- **Rationale**: 学习流程状态切换频繁且跨组件，集中状态可减少重复逻辑与状态错乱。
- **Alternatives considered**:
  - 仅组件本地状态：跨页面复用与回滚能力差。
  - 重型状态管理方案：超出 MVP 复杂度需求。

## 决策 3：离线能力范围

- **Decision**: MVP 阶段优先离线支持“已导入词书学习、学习进度保存、基础设置保存”。
- **Rationale**: 直接服务地铁/校园弱网场景，且实现成本可控，符合核心价值主张。
- **Alternatives considered**:
  - 全量离线（含 OCR/AI）：第三方能力离线不可行且复杂度过高。
  - 完全不做离线：与核心复习场景冲突。

## 决策 4：词条补全链路

- **Decision**: 采用“基础词典数据优先 + AI 个性化补充”双层策略。
- **Rationale**: 兼顾稳定性、成本与生成质量，减少完全依赖大模型带来的延迟与波动。
- **Alternatives considered**:
  - 全量 AI 生成：成本和响应不稳定。
  - 仅词典：个性化与趣味性不足。

## 决策 5：动画与反馈策略

- **Decision**: 闪卡翻转、滑动、局部庆祝、全局庆祝采用统一动画体系，确保移动端优先体验。
- **Rationale**: 学习工具的持续使用高度依赖即时反馈与交互流畅度，动画一致性影响留存。
- **Alternatives considered**:
  - 纯静态界面：可用但缺少激励反馈。
  - 每个页面独立动画实现：维护成本高且体验不一致。

## 决策 6：文案与 UI 规范执行

- **Decision**: 所有界面文案默认中文；涉及 UI 任务默认使用 `ui-ux-pro-max-skill`。
- **Rationale**: 与项目宪章一致，保证认知负担最小化和视觉一致性。
- **Alternatives considered**:
  - 中英混排：术语成本高、用户阅读负担增加。

## 文案核对清单（T045）

- 首页、学习页、生词页、设置页用户可见文案均已默认中文。
- 特殊单词例外：`OCR`、`API`、`PWA`、`Web Speech API` 保留英文。
- 按钮、提示、状态文案语气统一为“简短指令式中文”。
